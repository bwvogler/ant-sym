# Beads sync (the `ja` database)

Moved from CLAUDE.md (ja-fnd.8); CLAUDE.md keeps the rules an agent needs every session. Where AGENTS.md says `refs/dolt/data`, read `beads-dolt`.

The `ja` database syncs through the **`beads-dolt` branch**, not `refs/dolt/data`: the cloud-session git proxy rejects pushes to `refs/dolt/*` (403) but accepts branches, so the Dolt remote's data ref (`git_ref`) points at `refs/heads/beads-dolt`. Don't merge, rebase or delete that branch (or `__dolt_remote_info__`, which Dolt creates beside it); they hold Dolt objects, not code. `scripts/beads-sync.sh` handles it and the hooks in `.claude/settings.json` run it: `start` on SessionStart (bootstraps a fresh clone from the branch, then pulls; a local database with its own history, from `bd init` or a JSONL import, is moved to `.git/beads-sync/` and replaced by the shared one, with its newer or extra issues replayed on top and pushed), `push` on Stop (async; skips if nothing changed; pull-merge-retry on rejection). Neither creates the branch; only `scripts/beads-sync.sh seed` does, by hand. The branch was seeded on 2026-11-02 from a three-way merge of `.beads/issues.jsonl` across every branch (90 issues), so from now on the Dolt database is the record: change issues with `bd`. `issues.jsonl` is a local export, not in git. Run `scripts/beads-sync.sh push` by hand before ending a session that filed or closed beads; plain `bd dolt push` also works once `start` has run. The database was started fresh on 2026-11-01, and issues before that stay in the original jev-ants tracker. Cloud sessions need bd installed by the environment setup script: `apt-get install -y libicu-dev && go install github.com/steveyegge/beads/cmd/bd@v1.3.2 && ln -sf "$(go env GOPATH)/bin/bd" /usr/local/bin/bd` (needs Go ≥ 1.26.5, fetched automatically; ~3 min). `AGENTS.md` carries the full beads workflow block; where it says `refs/dolt/data`, read `beads-dolt`.
