# jev-ants — agent instructions

Two ant colonies and a fungus on one map, each ant steered by a Jev decision. (The original picture mode, where ants form typed or uploaded images, was removed on 2026-11-02; PRD §1–8 keep its history and measurements.) Single user, localhost, no auth, no database. Read `docs/vision.md` first for the goal (one policy per species fed only by the senses; a fungus that works through them), then `docs/PRD.md`: it holds every product decision and the measured Jev numbers. Research notes are indexed in `docs/README.md`.

## Writing for agents
`docs/agent-guide.md`: what goes in this file, skills, hooks or docs (the size budget a test holds), and the code style beyond Prettier and oxlint. Read it before changing this file.

## Patterns to copy, not reinvent
- Sibling apps: `../lingo-dojo` (closest: `web/server/api.ts` same-origin `wrap()`, Tailwind v4 `@theme inline` tokens in `web/src/index.css`, `.oxlintrc.json`), `../jev-router` (the only other Jev caller: `hooks/policy.ts` has the wire shape and a pure request-builder / response-reader split worth copying).
- Port **38500**, `strictPort`, `usePolling` watcher (FSEvents is unreliable on this machine). Lingo Dojo is 38400, Atlas 38300, Wine Guide 38200, Basecamp 38100.
- Every API route goes through `wrap()` with the same-origin check. No exceptions.
- `JEV_API_KEY` comes from the shell environment. Never read it in the browser, never commit it, never log it.
- New ant behaviour comes from the policy over **sensed** state (see the sense table in `docs/vision.md`). Don't add scripted choices that read global state an ant can't sense: the chamber table, other nests' coordinates, colony-wide counts. Removing one is progress; strike its row in the vision gap table and close its `ja-k4k` bead. A sense not in the table needs a research note with primary sources first.
- `web/src/colony/` (colony, nest, fungus) is pure TypeScript with no DOM; `node --test` covers it directly. The canvas renderer and React are thin layers over it. Code outside it (the page, the server, the maintained scripts) imports from `web/src/colony/index.ts`, never from a module file (`ui/tests/colonyIndex.test.ts` holds that line; `experiment.ts`, the assay harness, is imported by name). Shared words (modes, stances, situations, trail levels) live in `colony/vocab.ts`, a leaf that imports no colony code.
- Jev requests go through the server's connection pool. A single Node `fetch` dispatcher serialises parallel requests (measured: 10 × 50 ants stacked to 2.9 s; separate connections 0.65 s). Keep the test that proves overlap.
- Spend is real, at $0.042/M input tokens (`USD_PER_INPUT_TOKEN`). Spend nothing while answers are cached: Jev is asked only for a situation with no answer under the words in force (preset or the player's own); the first such miss starts a run, which stays open until the page closes. The ceiling is one overall daily budget in the server's ledger (`JEV_DAILY_USD`, default $0.10 a UTC day, kept in `data/jev-budget.json` across restarts; PRD §50.11), not per-run caps. The measured tokens per question and $/h of each lane (mode, stance, the six response lanes; the fungus lane ~770 tokens a situation, ~43 to a request) are in PRD §50.19 and §54.4–54.5; `npm run colony-cost` (add `--one` for one world) and `node scripts/fungus-cost.mjs` estimate them offline. Every change to a state schema, legend or question changes the hourly cost; note the new figure for that lane in the PR.

## New mechanics
A new mechanic or behaviour (a sense, an action, a lever, a lane) goes through the `adding-mechanics` skill (`.claude/skills/adding-mechanics/`, or `/adding-mechanics <idea>`): primary research, the translation to sensed cues, the case for play, then a committed note, PRD section and bead epic before code. While it is active, a hook blocks edits under `web/` and `scripts/` until `check-plan.sh` passes. Bug fixes and tuning don't need it. Its own tests: `.claude/skills/adding-mechanics/scripts/test.sh`.

## Work tracking
Beads: `bd ready` for unblocked work, `bd show <id>` for context, `bd close <id>` when done. Prefix `ja`. One PR per milestone, agent review before merge (the `reviewing-prs` skill or the `pr-reviewer` agent: one posted review, measured findings, decisions to beads; its hooks' tests: `.claude/skills/reviewing-prs/scripts/test.sh`). File new work as beads, not TODO comments.

The `ja` database syncs through the **`beads-dolt` branch**, not `refs/dolt/data`: the cloud-session git proxy rejects pushes to `refs/dolt/*` (403) but accepts branches, so the Dolt remote's data ref (`git_ref`) points at `refs/heads/beads-dolt`. Don't merge, rebase or delete that branch (or `__dolt_remote_info__`, which Dolt creates beside it); they hold Dolt objects, not code. `scripts/beads-sync.sh` handles it and the hooks in `.claude/settings.json` run it: `start` on SessionStart (bootstraps a fresh clone from the branch, then pulls; a local database with its own history, from `bd init` or a JSONL import, is moved to `.git/beads-sync/` and replaced by the shared one, with its newer or extra issues replayed on top and pushed), `push` on Stop (async; skips if nothing changed; pull-merge-retry on rejection). Neither creates the branch; only `scripts/beads-sync.sh seed` does, by hand. The branch was seeded on 2026-11-02 from a three-way merge of `.beads/issues.jsonl` across every branch (90 issues), so from now on the Dolt database is the record: change issues with `bd`, never by editing `issues.jsonl`, which is only an export. Run `scripts/beads-sync.sh push` by hand before ending a session that filed or closed beads; plain `bd dolt push` also works once `start` has run. The database was started fresh on 2026-11-01, and issues before that stay in the original jev-ants tracker. Cloud sessions need bd installed by the environment setup script: `apt-get install -y libicu-dev && go install github.com/steveyegge/beads/cmd/bd@v1.3.2 && ln -sf "$(go env GOPATH)/bin/bd" /usr/local/bin/bd` (needs Go ≥ 1.26.5, fetched automatically; ~3 min). `AGENTS.md` carries the full beads workflow block; where it says `refs/dolt/data`, read `beads-dolt`.

## Build & test
```sh
npm --prefix web install
npm run dev                    # http://localhost:38500
npm test                       # every tier below, ~4 min on 4 cores; node --test, 120 s per file here and in the soak tier, 60 s in unit, int and golden (the limit is a whole file, and files run side by side: split a file before it nears it)
npm run test:unit              # the quick tier (files under ~1.5 s alone: ui, server, worker, colony/tests/unit), ~9 s
npm run test:watch             # the unit tier on every save (node --test --watch)
npm run test:int               # colony/tests/int and ui/tests/int: files of 1.5-12 s
npm run test:soak              # colony/tests/soak: files over 12 s and the *.soak.test.ts long games (CI shards it 3 ways: `-- --test-shard=1/3`)
npm run test:golden            # the fast golden masters (colony/tests/golden)
node --test --test-name-pattern='stranger' web/src/colony/tests/int/colony.test.ts   # one file, or the tests of it whose name matches
npm run format                 # Prettier (width 140, Tailwind class order) over web/src, server, worker, shared and the scripts; `format:check` is what CI runs. A bulk reformat commit goes in .git-blame-ignore-revs
npm run test:slow              # whole-game guards (web/src/colony/tests/slow): ~5 min; run before merging colony changes
npm run e2e                    # one world in Chromium (scripts/e2e-one-world.mjs): switch views, linked clicks, follow through a hole, the pen by a click, the Fungus panel's tooltips, the tutorial; ~40 s; uses the machine's playwright, spends nothing
node scripts/colony-cost.mjs   # offline estimate of a colony game's cost: tokens per question from request size, $/h (no key, no spend)
npm run exp -- all --seeds 1-10   # behaviour assays (web/src/colony/experiment.ts), offline; --set sweeps, --policy cache:<file> replays Jev
npm run exp -- game --seeds 1 --log summary   # game journal (colony/journal.ts) per run in experiments/out/journal/; summary, detail, verbose (mode changes: add ant=<i>); page: ?log=<spec>
node scripts/colony-live.mjs all --budget 0.10   # live: Jev against the local rule per lane; saves replayable caches (experiments/out/)
node scripts/precache.mjs --import experiments/caches/<live-check>-*.json   # no spend: ship the answers a live check got (colony-live caches) as the preset doctrines' answers in web/public/precache; do this when precache.test fails (a legend, question or version moved)
```

`scripts/*.mjs` are the maintained tools: `npm run typecheck` checks them as JavaScript against the colony's types (`web/tsconfig.scripts.json`, not strict; `e2e-one-world.mjs` is left out, it only drives the page) and `npm run lint` lints them, so a rename in the core fails there. `scripts/lab` holds one-off measurements (benches, spikes) that fed a PRD section: not checked, run from the repo root; the PRD names them by their old path (`scripts/<name>.mjs`).

The page ships Jev's answers (`web/public/precache/`, ja-lo8.3) and plays cached answers whether or not a run is on; a lane whose words changed plays the local rule until the new answers arrive (ja-lo8.15); earlier words' answers play, stale, only while Jev can't run (`ColonyJev.canAsk`, set from `policyLock`). A change to a colony legend, question or brain version must re-ship them in the same PR: import the answers its live check got (`--import`, free), rather than asking every situation (`scripts/precache.mjs` without `--import`, ~$0.12 for the mode lane: only when the owner asks). Where nothing ships, a preset plays the local rule.

A change that should not alter behaviour must keep the golden masters bit-exact (`tests/golden/golden.test.ts`, `tests/golden/oneWorldGolden.test.ts`, `tests/slow/golden.test.ts`); one that should re-records them (`GOLDEN_WRITE=1`) and says so in its PR. Tune behaviour against the assays: compare `npm run exp` with the baseline (PRD §42), choose by the worst seed, confirm on seeds 11–20.

Merges to `main` deploy `web/dist` to the root of the `gh-pages` branch (`.github/workflows/pages.yml`, `BASE_PATH=/ant-sym/`). Every PR to `main` gets a preview at `/ant-sym/pr-preview/pr-<n>/` (`preview.yml`). Pages has no API of its own. Built with `VITE_JEV_API` (from the repository variable `JEV_API_URL`), a Pages build calls the hosted proxy `web/worker` (a Cloudflare Worker over the same reply functions as the dev server, `server/replies.ts`, which must stay free of `node:fs` and module-load file paths; behind a passphrase, an origin allowlist and a daily cap; `docs/hosting.md`). Built without it, `ui/backend.ts` finds no backend and the UI disables Jev. New fetches to the API must go through `apiUrl()` with `apiHeaders()`, never a bare `/api/...`. The Worker is the one place that accepts a cross-origin request, and only from `ALLOWED_ORIGINS`.

The test script must not use `--test-force-exit`. On Node 22, combined with `--test-timeout`, it sometimes ends a test file early and drops its remaining tests without a failure; runs reported 216 or 224 tests, all green (2026-11-01). Schedulers are disposed in `afterEach`, so nothing keeps the process alive without it.

Editing `web/server/*.ts` does **not** restart the running Vite (measured 2026-10-25: the old ledger kept serving after a branch switch). Restart `npm run dev` after server changes; `/api/health` shows the live run summary shape, so check it has the field you added.

Worktrees: never symlink `web/node_modules` into a worktree. A symlink is not a directory, so it slips past the ignore rule and `git add -A` commits it; checking that commit out elsewhere replaces the real folder with the link (happened 2026-10-25). Run `npm --prefix web ci` in the worktree instead (the only lockfile is `web/package-lock.json`).
